# 每日自动领取 WorkBuddy 每日登录奖励 100 积分（自动化提示词）

> 以下整段内容作为 `automation_update`（mode=create / update）的 `prompt` 字段。Agent 运行此任务时，全程无需询问用户，跑完再汇报。
>
> ⚠️ 2026-10-27 实测修正：**不要绕到网页版 growth-center 去找签到入口。**正确入口就在客户端窗口左下角，点一下就完成。

---

用 Windows 桌面自动化（windows-mcp 的 Snapshot / Click / App / Wait）领取 WorkBuddy 客户端的【每日登录奖励】100 Credits，只做这一件事。

## 领取入口（唯一正确）

WorkBuddy 客户端窗口**左下角**有一张「Buddy加油站」小卡片：
`Buddy加油站 / 每日 +100 积分` + 右侧一个黑色 **`立即领取`** 按钮。点它即可。

## 执行步骤

1. **确保 WorkBuddy 窗口在前台**（否则点击会落到上层窗口）：
   - 优先用 App 工具 `mode=switch, name=WorkBuddy`。
   - 若切不动，跑技能自带的 `scripts/focus_workbuddy.py`（纯 ctypes 置前，不受 Add-Type 拦截）。
2. **用文字定位按钮（禁止硬编码坐标）**：Snapshot（`use_ui_tree=true, use_vision=true`）读左下角卡片，找到文本为 **`立即领取`** 的按钮。
   - 找不到 `立即领取` → 今天已领过或入口未出现。再 Snapshot 确认卡片文案（可能已变成「N 余额积分可用」或「今日已领取」「明日再来」），**如实汇报并结束，不要点任何其它东西**。
3. **点击**该 `立即领取` 按钮（Click，loc 用 Snapshot 给出的坐标）。
4. **等 2 秒，再 Snapshot 一次确认**：
   - `立即领取` 按钮消失、卡片变为「余额积分可用」→ 领取成功；
   - 读取卡片上的积分余额数字。
5. **汇报**：是否领到 100 积分、领取前后积分余额数字、判定依据（按钮消失/文案变化）。

## 安全约束（必须严格遵守，不可绕过）

- 只允许点击文本为 `立即领取` 的按钮。
- **严禁**点击「立即投稿」「充值余额」「升级套餐」「去重构」「设置」「外观」「记忆与自动化」「意见反馈」「检查更新」「退出登录」，以及「Buddy加油站」展开菜单里的任何奖励项。
- 若弹出协议，只针对「每日登录奖励」勾选确认并同意；**若协议要求开启盲盒/抽奖，立即停止并汇报**。
- 若需要重新登录或出现验证码，立即终止操作并汇报需人工处理。
- 界面改版导致文字匹配失败时，停止并汇报，不要凭坐标乱点。

## 不要做的事（血泪教训，2026-10-27）

- ❌ 不要去挖 `app.asar` 找 `/billing/meter/daily-checkin` 接口。
- ❌ 不要去逆向 bearer token / 读 Electron leveldb / 解 keyblob。
- ❌ 不要开浏览器去 `https://www.workbuddy.cn/profile/growth-center` 找签到——那页是「限时连登抽奖」活动（+50 积分 + 连登奖励），**不是**每日 100 积分。
- ❌ 不要做截图裁剪放大之类的"像素级验证"。验证只看：按钮是否消失 + 余额数字。
- ❌ 不要在客户端没在前台时盲点坐标；先置前。
